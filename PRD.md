# PRD: Заполнение табеля 1С из задачи Битрикс24

## Цель

Сотрудник, работающий в 1С со своим табелем (документ «Табель», `Документ.гем_Табель`), добавляет в него строку по задаче Битрикс24. Задачу он выбирает из списка своих задач, время и тип времени указывает в небольшом окне. Содержание, контрагент (по компании CRM задачи) и номер задачи подставляются автоматически.

## Участники и системы

- **Битрикс24 (облако, рабочий портал).** Источник задач, пользователей, компаний CRM и их реквизитов. Функция только читает данные из Битрикс24 и ничего в него не записывает.
- **1С:КА (сервер в офисе).** Здесь находятся табель, физические лица, пользователи и контрагенты. Кнопка и окно заполнения работают в 1С. Доработки выполняются в отдельном расширении `Б24ТабельИзЗадачи` («Б24: табель из задачи») только на встроенном языке 1С (BSL), без HTML/JS, отдельного сервера и приложения Битрикс24. Расширение независимо от расширения `Б24ПрототипЭтап1` (связь заказов клиента с задачами Битрикс24): оно ставится, обновляется и удаляется отдельно и не меняет `Б24ПрототипЭтап1`.
- **Пользователь.** Сотрудник, который входит в 1С под своим пользователем. Пользователь 1С связан с физическим лицом сотрудника, а в карточке физического лица указан e-mail, совпадающий с e-mail его пользователя Битрикс24. Заполнять табель по задаче он может, если является её постановщиком, исполнителем или соисполнителем.

## Фича 1. Кнопка «Заполнить из задачи Б24»

В форме документа «Табель» (`ФормаДокумента`) в командной панели таблицы «Табель», рядом с кнопкой «Добавить», есть кнопка «Заполнить из задачи Б24». Нажатие открывает окно «Заполнить из задачи Битрикс24» (фичи 3 и 4).

Кнопка работает в новом, ещё не записанном табеле и в уже существующем, проведённом или непроведённом. Строка всегда добавляется в табель, открытый в этой форме. Дата строки — дата этого табеля.

Кнопка доступна тогда же, когда доступна кнопка «Добавить» таблицы «Табель»: сейчас это автор табеля и пользователи с полными правами. Когда «Добавить» недоступна, недоступна и «Заполнить из задачи Б24».

## Фича 2. Кто и в какой табель может заполнять

Пользователь определяется по входу в 1С. Его физическое лицо берётся из карточки пользователя 1С. Пользователь Битрикс24 находится по e-mail из карточки этого физического лица (вид контактной информации «Электронная почта»): e-mail сравнивается с e-mail активных сотрудников компании в Битрикс24 (внешние и почтовые пользователи не подходят) без учёта регистра и пробелов по краям. Если у физического лица указано несколько адресов, подходит любой из них; если ни один не найден, в сообщении перечислены все адреса через запятую. Каждый адрес сотрудника должен быть только в его карточке: иначе по чужому адресу можно было бы получить чужие задачи. Каждое успешное сопоставление «пользователь 1С → пользователь Битрикс24» записывается в журнал регистрации.

Заполнять из задачи можно только свой табель: сотрудник, указанный в табеле, должен совпадать с физическим лицом текущего пользователя 1С.

При нажатии кнопки 1С выполняет проверки в порядке, указанном в таблице: сначала проверки в 1С, затем обращения к Битрикс24. Если проверка не пройдена, окно открывается без списка задач и полей: в нём только сообщение и кнопка «Закрыть». Табель не меняется.

| Ситуация | Сообщение |
|---|---|
| Адрес вебхука не указан в настройках | «Не настроено подключение к Битрикс24. Обратитесь к администратору» |
| В табеле не указан сотрудник | «Сначала укажите сотрудника в табеле» |
| Пользователь 1С не связан с физическим лицом | «Ваш пользователь 1С не связан с физическим лицом. Обратитесь к администратору» |
| В табеле указан другой сотрудник | «Заполнять из задачи Битрикс24 можно только свой табель» |
| В карточке физического лица не указан e-mail | «В карточке физического лица ‹ФИО› не указан e-mail. Обратитесь к администратору» |
| Тот же e-mail указан у другого физического лица в 1С (помеченные на удаление не учитываются) | «E-mail ‹e-mail› указан в карточках нескольких физических лиц. Обратитесь к администратору» |
| Битрикс24 не отвечает | «Битрикс24 недоступен. Попробуйте позже» |
| Битрикс24 отклоняет адрес вебхука или пользователь, создавший вебхук, не администратор Битрикс24 | «Не настроено подключение к Битрикс24. Обратитесь к администратору» |
| Битрикс24 вернул неожиданную ошибку | «Битрикс24 вернул ошибку. Обратитесь к администратору» |
| В Битрикс24 нет активного пользователя с таким e-mail | «В Битрикс24 нет пользователя с e-mail ‹e-mail›. Обратитесь к администратору» |
| В Битрикс24 по адресам сотрудника найдено несколько разных пользователей | «В Битрикс24 несколько пользователей с e-mail ‹e-mail›. Обратитесь к администратору» |

Выбрать можно только задачу, в которой пользователь — постановщик, исполнитель или соисполнитель. Статус задачи не важен: строку можно добавить и по завершённой задаче. Если по номеру или ссылке (фича 3) найдена задача, в которой пользователь не участвует в этих ролях, например является только наблюдателем, в окне показывается сообщение «Заполнять табель по задаче могут только постановщик, исполнитель и соисполнители», а кнопка «Добавить в табель» недоступна. Название такой задачи, её компания и контрагент не показываются: иначе, перебирая номера, можно было бы читать чужие задачи.

## Фича 3. Окно: выбор задачи

Окно называется «Заполнить из задачи Битрикс24». Верхняя часть окна — «Задача». Пока окно открыто, табель за ним недоступен для правки: окно блокирует его. Пока 1С загружает задачи из Битрикс24, в окне показывается «Загрузка задач из Битрикс24…»; окно в это время не реагирует на щелчки. Если список не загрузился, окно остаётся открытым, а задачу можно найти по номеру или ссылке; чтобы загрузить список заново, окно открывают ещё раз.

**Список задач.** В списке находятся задачи, где пользователь — постановщик, исполнитель или соисполнитель: все незавершённые и завершённые не раньше чем за 30 дней до даты табеля. Граница включается целиком: задача, завершённая в день ‹дата› (дата табеля минус 30 дней) в любое время, в списке есть. Завершённой считается задача в статусе «Завершена». Задачи в статусах «Ждёт контроля» и «Отложена» считаются незавершёнными. Список загружается один раз, при открытии окна: задачу, появившуюся позже, вводят по номеру или ссылке. В списке не больше 1000 самых новых задач; если их больше, над списком написано «Показаны не все задачи. Если нужной нет, введите её номер или ссылку». Под списком написано: «Незавершённые задачи и задачи, завершённые с ‹дата›, где вы постановщик, исполнитель или соисполнитель», где ‹дата› — дата табеля минус 30 дней.

| Колонка | Содержимое |
|---|---|
| № | Номер задачи |
| Задача | Название задачи |
| Моя роль | Постановщик, исполнитель или соисполнитель; если ролей несколько — все через запятую |
| Крайний срок | Дата крайнего срока или «без срока» |
| Статус | Статус задачи в Битрикс24: «Новая», «Ждёт выполнения», «Выполняется», «Ждёт контроля», «Завершена», «Отложена», «Отклонена» |
| Компания CRM | Название компании из «Элементов CRM»; «—», если компании нет; «2 компании», «5 компаний», «21 компания», если их несколько. Компания, удалённая из CRM, не считается |
| Активность | Дата и время последней активности в задаче |

**Сортировка.** Над списком три переключателя: «По активности» (по умолчанию, сначала задачи с самой свежей активностью), «По крайнему сроку» (сначала ближайший срок, то есть просроченные задачи первыми, задачи без срока в конце) и «По номеру» (сначала задачи с большим номером). При равных значениях выше задача с большим номером.

**Поиск.** Поле «Поиск по номеру или названию» оставляет в списке задачи, у которых номер или название содержит введённый текст, без учёта регистра; «е» и «ё» не различаются. Список сокращается по мере ввода, без обращения к Битрикс24; текст поиска не длиннее 100 символов. Если выбранная задача не подходит под поиск, выбор не снимается: под полем номера по-прежнему написано «Выбрана задача №‹номер›», «Добавить в табель» доступна. Поиск только сужает видимые строки. Если ничего не найдено (или у сотрудника нет подходящих задач), в списке написано «Ничего не найдено. Введите номер или ссылку на задачу.»

**Номер или ссылка.** В поле «или номер / ссылка на задачу» можно ввести номер задачи (в том числе «#10180», «№ 10180», «10 180») или вставить ссылку на карточку задачи, скопированную из Битрикс24 (личную или проекта, на просмотр или редактирование). Поле не длиннее 300 символов. Найденная задача выбирается, даже если её нет в списке (например, завершена раньше, чем за 30 дней до даты табеля): строка в списке не подсвечивается, под полем номера написано «Выбрана задача №‹номер›». На неё действуют правила фичи 2. Если задачи с таким номером нет, показывается «Задача №‹номер› не найдена в Битрикс24». Если введено не число и не ссылка на задачу, показывается «Введите номер задачи или ссылку на задачу Битрикс24». Если введённая задача не подошла (не найдена, не число, сотрудник в ней не участвует, задача не из проекта режима тестирования), прежний выбор снимается и «Добавить в табель» недоступна, пока сотрудник не выберет задачу снова. Если Битрикс24 не ответил, прежний выбор сохраняется. Пока 1С ищет задачу по номеру, рядом с полем номера написано «Поиск задачи в Битрикс24…». Пустое поле номера только очищает сообщение: запроса нет, выбор не меняется. Щелчок по строке списка очищает поле номера и его сообщение.

**Выбор задачи.** Задача выбирается щелчком по строке списка. При открытии окна задача не выбрана. Выбранная строка подсвечена, под полем номера написано «Выбрана задача №‹номер›». При выборе задачи поле «Содержание» заполняется её названием, а контрагент (фича 6) показывается сразу: 1С определяет его заранее, для задач списка при загрузке списка, для задачи по номеру или ссылке при её поиске, поэтому щелчок по строке к Битрикс24 не обращается. При выборе другой задачи «Содержание» заменяется её названием, даже если сотрудник его изменил.

## Фича 4. Окно: поля строки табеля

Нижняя часть окна называется «Строка табеля за ‹дата табеля›». Дата в окне не выбирается: это дата открытого табеля.

| Поле | Значение по умолчанию | Правила |
|---|---|---|
| Время начала | Время окончания строки табеля с самым поздним временем начала. Если в табеле нет строк — 09:00. Если у этой строки не указано время окончания — пусто | Обязательное. Время вводится с клавиатуры (любое, например 10:07) или выбирается из списка с шагом 5 минут. 00:00 считается «не указано» |
| Время окончания | Пусто | Необязательное. Вводится или выбирается так же, как время начала, должно быть позже времени начала |
| Тип времени | «Клиент (УД)» | Выпадающий список типов времени «Клиент» и «Офис» из 1С |
| Содержание | Название выбранной задачи | Свободный текст, можно изменить или очистить |
| Контрагент | Определяется по фиче 6 | Только для просмотра |

В списке типов времени — значения перечисления «Типы времени», название которых начинается с «Клиент» или «Офис», в порядке перечисления, кроме «Офис (командировка)» и «Офис (собрания)»: при этих типах табель не допускает контрагента. Типы «Обед», «Дорога (…)», «Пропуск (…)», «Офис (командировка)» и «Офис (собрания)» в окне не выбираются.

Если контрагент найден, показано его наименование и пометка «найден в 1С по БИН ‹номер›». Если не найден, вместо наименования показан текст причины из фичи 6.

Внизу окна две кнопки: «Добавить в табель» и «Отмена». «Отмена» закрывает окно, табель не меняется. Закрытие окна крестиком или клавишей Esc действует как «Отмена» и ни о чём не спрашивает.

Если время начала и окончания пересекается с временем другой строки табеля, под временем показывается предупреждение «Пересекается со строкой №‹номер› (‹начало›–‹окончание›)» с первой такой строкой (по номеру строки в табеле). Если время окончания не указано, пересечением считается начало новой строки внутри другой строки (начало не раньше её начала и раньше её окончания). Строки табеля без времени начала или окончания в проверке не участвуют. Касание концов (10:00–11:00 и 11:00–12:00) пересечением не считается. Кнопка «Добавить в табель» при этом доступна: сотрудник решает сам.

Кнопка «Добавить в табель» недоступна, пока не выбрана задача, не указано время начала или время окончания не позже времени начала. У ошибочного поля показывается подсказка: «Укажите время начала» или «Время окончания должно быть позже времени начала». Подсказка про время начала видна сразу, если время начала по умолчанию пусто.

При нажатии «Добавить в табель» 1С ещё раз проверяет выбранную задачу в Битрикс24 (существование, роль, проект режима тестирования); пока идёт проверка, внизу окна написано «Проверка задачи в Битрикс24…», а кнопка недоступна. Если Битрикс24 не ответил, строка не добавляется: окно остаётся открытым с сообщением «Битрикс24 недоступен. Попробуйте позже», введённые данные сохраняются, кнопку можно нажать снова. Если задача больше не подходит (удалена, сотрудник в ней не участвует), окно показывает сообщение по фиче 2 или 3 и снимает выбор. В строку идёт контрагент, показанный в окне.

## Фича 5. Добавление строки в табель

Нажатие «Добавить в табель» добавляет новую строку в таблицу «Табель» открытого документа. Строки таблицы сортируются по времени начала, как перед добавлением строки кнопкой «Добавить», и новая строка встаёт на своё место. Окно закрывается, новая строка становится текущей. Если контрагент не найден и тип времени начинается с «Клиент», курсор встаёт в поле «Контрагент» новой строки; выбрать контрагента сотрудник может сам. Окно выбор контрагента само не открывает. При типах «Офис…» контрагент не обязателен: курсор в поле «Контрагент» не ставится, новая строка просто становится текущей.

| Поле строки | Значение |
|---|---|
| Контрагент | Найденный по фиче 6. Если не найден, поле пустое |
| Тип времени | Выбранный в окне |
| Время нач. | Указанное в окне |
| Время кон. | Указанное в окне. Если не указано, поле пустое |
| Содержание | Указанное в окне |
| ID Б24 | Номер задачи Битрикс24 |

Тип ПП не заполняется. Если время окончания указано, все расчётные поля строки (Факт, Норма, К оплате, Зарплата и другие) и итог «Всего зарплата» рассчитываются так же, как при ручном вводе времени в табеле. Если время окончания не указано, сотрудник позже вводит его в строке сам, и табель выполняет тот же расчёт. Остальные поля строки («Печать», «Проезд», «Заметки» и другие) получают те же значения, что у строки, добавленной кнопкой «Добавить».

Строка не записывается автоматически: табель становится изменённым, и сотрудник записывает или проводит его как обычно. Если закрыть табель без записи, строка не сохранится.

Каждое нажатие «Добавить в табель» добавляет новую строку. Повторное заполнение по той же задаче добавляет ещё одну строку, а существующие строки не меняются.

## Фича 6. Контрагент из компании CRM

Контрагент определяется только по компании, привязанной к задаче в поле «Элементы CRM». Название задачи и название компании для поиска контрагента не используются.

**Какая компания берётся.** Если в «Элементах CRM» привязана ровно одна компания, берётся она. Если привязано несколько компаний, контрагент не определяется. Если компании нет, а привязаны только сделки, контакты или другие элементы CRM, контрагент не определяется: компания из сделки или контакта не подтягивается. Компания, удалённая из CRM, но оставшаяся привязанной к задаче, считается отсутствующей.

**Сопоставление с контрагентом 1С.** Номер берётся из реквизитов компании в Битрикс24: из реквизита берётся первое заполненное из полей БИН (`RQ_BIN`), ИИН (`RQ_IIN`) и ИНН (`RQ_INN`). Так поддерживаются юрлица, индивидуальные предприниматели и компании с российским ИНН. Если у компании несколько реквизитов, используется первый (в порядке, в котором они показаны в карточке компании), где заполнено одно из этих полей. Заполненным считается поле, в котором есть цифры, и из него берутся только цифры: «2345 1261 2395» и «234512612395.» дают 234512612395, а «-» и «нет» — незаполненное поле. Реквизиты, отключённые в Битрикс24, не используются. Номер сравнивается с полем «БИН/ИИН» (`ИНН`) контрагента в 1С; пробелы по краям этого поля не мешают. Контрагенты, помеченные на удаление, не учитываются.

Если найден ровно один контрагент, он подставляется в строку. Если не найдено ни одного или найдено несколько, поле «Контрагент» в строке остаётся пустым, и сотрудник выбирает контрагента в строке табеля сам. Строка добавляется в любом случае.

| Ситуация | Текст в окне |
|---|---|
| В задаче нет компании CRM | «В задаче не указана компания CRM — выберите контрагента вручную» |
| В задаче несколько компаний CRM | «В задаче несколько компаний CRM — выберите контрагента вручную» |
| У компании в реквизитах не заполнен ни БИН, ни ИИН, ни ИНН | «У компании «‹название›» не заполнен БИН — выберите контрагента вручную» |
| В 1С нет контрагента с таким БИН | «Контрагент с БИН ‹номер› не найден в 1С — выберите контрагента вручную» |
| В 1С несколько контрагентов с таким БИН | «В 1С несколько контрагентов с БИН ‹номер› — выберите нужного вручную» |

## Фича 7. Колонка «ID Б24» в табеле

В табличную часть «Табель» документа `гем_Табель` добавляется колонка «ID Б24» — строка длиной 20 символов. Колонка добавляется через расширение `Б24ТабельИзЗадачи`, видна в основной форме документа (`ФормаДокумента`) и редактируется сотрудником. При заполнении из задачи в неё записывается номер задачи. В строках, добавленных вручную, колонка пустая. При копировании строки или табеля номер копируется вместе с остальными полями.

## Фича 8. Настройки интеграции и режим тестирования

В 1С есть форма «Настройки интеграции с Битрикс24». Её открывают пользователи с полными правами. В ней задаются:

- **Адрес входящего вебхука Битрикс24.** Вебхук создаёт администратор Битрикс24 с правами «Задачи», «CRM», «Пользователи» и «Рабочие группы». Последнее право нужно, чтобы показать название проекта в режиме тестирования. Для комментариев задач в ИИ (фича 15) вебхуку нужно ещё право «Чат и уведомления». После сохранения адрес в форме не показывается целиком.
- **Режим тестирования** — флажок.
- **Проект для тестирования** — ID проекта Битрикс24.

Форма открывается из раздела «НСИ и администрирование» → «Настройка интеграции». Пользователям без полных прав пункт не виден.

**Поля и кнопки формы.** Поля: «Адрес входящего вебхука Битрикс24», «Режим тестирования», «Проект для тестирования (ID)». Кнопки: «Удалить адрес», «Проверить подключение», «Записать и закрыть», «Закрыть». Под полем адреса подсказка: «Создайте в Битрикс24 входящий вебхук с правами «Задачи», «CRM», «Пользователи» и «Рабочие группы» и вставьте его адрес».

**Адрес вебхука.**
- Сохранённый адрес показан надписью «Сохранён: ‹адрес со скрытым ключом›», например «Сохранён: https://‹портал›/rest/30/***/». Если адреса нет, написано «Не указан». Поле ввода после открытия формы и после записи пустое. Адрес в поле ввода скрыт, как пароль.
- Новый адрес, вставленный в поле, заменяет старый. Пустое поле старый адрес не стирает. «Удалить адрес» стирает его при записи; «Закрыть» без записи оставляет старый.
- При записи у адреса убираются пробелы по краям и имя метода в конце (адрес-пример из Битрикс24 вида `…/profile.json`). Принимается только адрес портала облачного Битрикс24 вида `https://‹портал›.bitrix24.‹зона›/rest/‹номер›/‹ключ›/` (например, `https://company.bitrix24.kz/rest/30/‹ключ›/`), иначе запись не выполняется и показывается «Адрес вебхука должен иметь вид https://‹портал›.bitrix24.‹зона›/rest/‹номер›/‹ключ›/». Подключение к Битрикс24 при записи не проверяется.
- Если режим тестирования включён, а проект не указан, запись не выполняется и показывается «Укажите ID проекта для тестирования». Когда флажок снят, поле проекта недоступно, но указанное значение сохраняется.
- **«Проверить подключение»** обращается к Битрикс24 по адресу из поля ввода, а если поле пустое, по сохранённому, и ничего не записывает. Под кнопками показывается результат построчно:
  - «Подключение работает. Вебхук создан пользователем ‹Имя Фамилия›.» (если у вебхука нет права «Пользователи»: «Подключение работает. Вебхук создан пользователем с ID ‹номер›.»);
  - «Права вебхука: Задачи — есть, CRM — есть, Пользователи — есть, Рабочие группы — нет, Чат и уведомления — нет.»;
  - «У пользователя ‹Имя Фамилия› нет прав администратора Битрикс24. Сотрудники не смогут заполнять табель из задач.» (только если прав нет);
  - в режиме тестирования: «Проект для тестирования: «‹название›».» или «Проект для тестирования с ID ‹ID› не найден.»;
  - если адрес не указан: «Не указан адрес вебхука.»; если адрес неверного вида: «Адрес вебхука должен иметь вид https://‹портал›.bitrix24.‹зона›/rest/‹номер›/‹ключ›/»;
  - если Битрикс24 отклоняет адрес: «Битрикс24 отклоняет адрес вебхука.»; если не отвечает: «Битрикс24 недоступен. Попробуйте позже».
- Если закрыть форму с несохранёнными изменениями, 1С спрашивает, сохранить ли их. Изменения начинают действовать при следующем открытии окна «Заполнить из задачи Битрикс24».
- После установки расширения режим тестирования выключен, проект и адрес не указаны.
- Над полями формы показываются предупреждения, если они есть: «В базе установлено тестовое расширение «‹имя›». В рабочей базе его быть не должно.» (для расширений YAXUNIT и Б24ТабельИзЗадачиТесты) и «У расширения «Б24: табель из задачи» отключена защита от опасных действий.»

Вебхук работает с правами создавшего его администратора: этот пользователь должен видеть все задачи и компании CRM. Если его отключить или лишить прав администратора, подключение перестанет работать, и 1С будет показывать «Не настроено подключение к Битрикс24. Обратитесь к администратору».

Когда режим тестирования включён:
- в списке задач показываются только задачи проекта для тестирования;
- над списком написано «Режим тестирования: показаны только задачи проекта «‹название проекта›»»;
- при вводе номера или ссылки на задачу другого проекта показывается «В режиме тестирования доступны только задачи проекта «‹название проекта›»», а кнопка «Добавить в табель» недоступна. Эта проверка выполняется раньше проверки роли (фича 2).
- если проекта для тестирования нет в Битрикс24 (удалён или ID указан неверно), окно показывает «Не настроено подключение к Битрикс24. Обратитесь к администратору», причина записывается в журнал регистрации.

На демо-базе КА режим тестирования включён, проектом для тестирования указан «[ТЕСТ] Табель из задачи». В рабочей КА режим тестирования выключен.

## Связь с Битрикс24 и безопасность

- 1С обращается к Битрикс24 по HTTPS через входящий вебхук из настроек (фича 8). Серверу 1С нужен исходящий доступ к порталу Битрикс24. Публиковать 1С на веб-сервере и устанавливать приложение в Битрикс24 не требуется.
- Функция только читает данные Битрикс24: пользователей, задачи, компании CRM и их реквизиты. В Битрикс24 ничего не записывается.
- Адрес вебхука хранится в безопасном хранилище 1С. Он не попадает в журнал регистрации, в тексты сообщений и в формы, кроме формы настроек.
- Вебхук даёт права администратора Битрикс24, поэтому: его создаёт отдельный технический пользователь-администратор Битрикс24 для интеграции; вебхук перевыпускается, если копию рабочей базы передали за пределы офиса, если администратор, имевший к нему доступ, ушёл, и при любом подозрении на утечку; в копиях рабочей базы (тестовых, учебных) адрес вебхука удаляется в форме настроек сразу после копирования.
- Каждое обращение к Битрикс24 записывается в журнал регистрации отдельной записью: метод, параметры, длительность, сколько записей получено. Ошибки записываются с кодом и описанием Битрикс24. Содержимое ответов (названия компаний, реквизиты) и адрес вебхука в журнал не попадают. E-mail в журнале записываются со скрытой частью до «@»: первый символ и «***», например `t***@example.com`; в сообщениях сотруднику адрес показывается полностью.
- Битрикс24 считается недоступным, если он не ответил за 30 секунд, вернул ошибку сервера, ответил не в формате JSON или сообщил о превышении лимита запросов. Лимит запросов и ошибку сервера 1С один раз повторяет через 2 секунды и только потом показывает сообщение; если за 30 секунд ответа нет, запрос не повторяется. Каждый запрос ждёт ответа не больше 30 секунд, после первого «недоступен» загрузка прекращается.
- Любой отказ в доступе (неверный или удалённый вебхук, у вебхука нет нужного права, тариф без REST, метод не найден, переадресация портала) сотрудник видит как «Не настроено подключение к Битрикс24. Обратитесь к администратору»; точный код ошибки администратор находит в журнале регистрации. Неожиданная ошибка Битрикс24, которая не относится ни к недоступности, ни к отказу в доступе, показывается как «Битрикс24 вернул ошибку. Обратитесь к администратору».
- Пользователь Битрикс24, создавший вебхук, должен быть администратором: при каждом открытии окна 1С это проверяет, иначе показывает «Не настроено подключение к Битрикс24. Обратитесь к администратору». Без этой проверки список задач молча оказался бы неполным.
- Если Битрикс24 не отвечает, когда окно уже открыто (загрузка списка или поиск по номеру или ссылке, включая определение контрагента), в окне показывается «Битрикс24 недоступен. Попробуйте позже». Окно остаётся открытым, введённые данные сохраняются.

## Тестовые данные и приёмка

Разработка ведётся на копии демо-базы КА у разработчика. Приёмка проходит на демо-базе КА на сервере офиса в режиме тестирования; функциональность проверяют реальные сотрудники. В Битрикс24 разработка и приёмка ведутся на рабочем портале с тестовыми компаниями и задачами. После приёмки расширение устанавливается в рабочую КА с предварительной резервной копией, в настройках указывается рабочий вебхук и выключается режим тестирования. Сотрудники, которые будут пользоваться функцией, указывают e-mail в Битрикс24 и в карточке своего физического лица в рабочей КА.

**Правила для тестовых данных:**

- Название каждой тестовой компании и задачи начинается с префикса «[ТЕСТ]», например «[ТЕСТ] АВИКА». На поиск контрагента префикс не влияет.
- Обмен CRM 1С ↔ Битрикс24 в разработке и приёмке не участвует.
- Тестовые задачи ставятся в проект «[ТЕСТ] Табель из задачи». Участники проекта — только проверяющие.
- У проверяющих пользователи 1С на демо-базе КА связаны с их физическими лицами, а e-mail в карточке физического лица совпадает с e-mail в Битрикс24.
- На время разработки используется e-mail разработчика из переменной `TEST_USER_EMAIL` в файле `.env` (в git не попадает, шаблон — `.env.example`). Он указан у пользователя Битрикс24 разработчика и в карточке физического лица пользователя, под которым разработчик входит в свою копию демо-базы КА.
- Тестовые данные создаются через REST по входящему вебхуку для разработки с правами «CRM», «Задачи», «Пользователи» и «Рабочие группы». Перед внедрением в рабочую КА этот вебхук перевыпускается.
- После приёмки тестовые компании, задачи и проект удаляются из Битрикс24, а строки табеля с номерами тестовых задач удаляются из демо-базы КА.

**Набор тестовых компаний.** У каждой компании в реквизитах заполнен БИН или ИИН контрагента из КА, если в таблице не сказано иное. Клиенты компании только казахстанские, поэтому компания с российским ИНН вживую не создаётся: поиск по полю «ИНН» проверяется автотестом.

| Компания | Реквизиты | Ожидаемый результат |
|---|---|---|
| Компания-юрлицо | БИН контрагента КА | Контрагент подставляется |
| Компания-ИП | ИИН контрагента КА | Контрагент подставляется |
| Компания с двумя реквизитами | Первые реквизиты без БИН, вторые с БИН контрагента КА | Контрагент подставляется по вторым реквизитам |
| Компания без реквизитов | — | «Не заполнен БИН», контрагент пустой |
| Компания с несуществующим БИН | БИН, которого нет в КА | «Не найден в 1С», контрагент пустой |
| Компания с БИН дубля | БИН, который в КА есть у двух контрагентов | «Несколько контрагентов», контрагент пустой |

**Набор тестовых задач.** В проекте «[ТЕСТ] Табель из задачи» к каждой компании из таблицы привязана своя задача, одна из этих задач завершена. Дополнительно в проекте есть задача с двумя привязанными компаниями (ожидается «несколько компаний CRM»), задача без компании (ожидается «не указана компания CRM») и задача, в которой проверяющий только наблюдатель. Вне проекта есть одна задача, в которой проверяющий — исполнитель.

**Сценарии приёмки:**

- **С1.** Сотрудник открывает свой табель, нажимает «Заполнить из задачи Б24» и выбирает задачу из списка. В табеле появляется строка с контрагентом, типом времени, временем, содержанием и номером задачи в «ID Б24». Табель записывается и проводится как обычно.
- **С2.** Задача выбирается по номеру и по ссылке на карточку задачи. Несуществующий номер и текст, который не является номером или ссылкой, дают соответствующие сообщения.
- **С3.** Поиск по номеру и по части названия; сортировка по активности, по крайнему сроку и по номеру. Завершённая тестовая задача есть в списке табеля за сегодня и отсутствует в списке табеля за дату позже даты её завершения плюс 30 дней.
- **С4.** Повторное заполнение по той же задаче добавляет вторую строку, первая не меняется.
- **С5.** Заполнение с временем окончания (Факт, Норма, К оплате, Зарплата и итог «Всего зарплата» совпадают с ручным вводом) и без него.
- **С6.** Все 6 компаний и задачи с двумя компаниями и без компании дают ожидаемый результат по контрагенту.
- **С7.** Задача, где проверяющий только наблюдатель, введённая по номеру: показывается сообщение о правах, добавить строку нельзя.
- **С8.** Чужой табель и табель без сотрудника: показываются соответствующие сообщения, окно не даёт заполнить строку. В табеле, открытом только для просмотра, кнопка недоступна.
- **С9.** Пользователь 1С без физического лица, физическое лицо без e-mail и e-mail, которого нет в Битрикс24: показываются соответствующие сообщения.
- **С10.** Режим тестирования: в списке только задачи проекта «[ТЕСТ] Табель из задачи»; задача вне проекта, введённая по номеру, не принимается.
- **С11.** Неверный адрес вебхука и отсутствие связи с Битрикс24: показываются соответствующие сообщения, введённые данные в окне сохраняются.
- **С12.** Ошибки ввода: без времени начала и с временем окончания не позже начала кнопка «Добавить в табель» недоступна, у поля показывается подсказка.
- **С13.** Колонка «ID Б24» видна и редактируется в форме табеля; в строках, добавленных вручную, она пустая.
- **С14.** В списке типов времени только типы «Клиент» и «Офис», кроме «Офис (командировка)» и «Офис (собрания)»; по умолчанию выбран «Клиент (УД)».
- **С15.** Время начала по умолчанию равно окончанию самой поздней строки табеля, в пустом табеле — 09:00, при самой поздней строке без окончания — пусто. Добавленная строка встаёт на место по времени начала. Пересечение с другой строкой даёт предупреждение, но строку добавить можно. Если контрагент не найден и тип времени «Клиент…», после добавления курсор стоит в поле «Контрагент» новой строки, а выбор контрагента сам не открывается; при типе «Офис…» курсор в «Контрагент» не ставится.

## Доработка. Заполнение «Содержания» с помощью ИИ

В окне «Заполнить из задачи Битрикс24» сотрудник может одной кнопкой попросить ИИ написать «Содержание» строки табеля. ИИ — модель OpenAI «GPT-5.6 Luna» (`gpt-5.6-luna`). Текст составляется из выбранной задачи (с её комментариями, если это включено в настройках, фича 15) и черновика сотрудника, по стандартным формулировкам из справочника шаблонов 1С и по правилам оформления табелей. ИИ заполняет только поле «Содержание». Список задач, контрагент, время, тип времени и добавление строки работают как прежде (фичи 1–8 PRD). Номера фич и сценариев продолжают PRD. Тексты надписей и сообщений этого раздела обязательны дословно.

### Фича 9. Кнопка «Заполнить с помощью ИИ»

В нижней части окна под полем «Содержание» есть кнопка «Заполнить с помощью ИИ». При наведении на неё показывается подсказка «ИИ составит содержание по задаче и тексту в поле. Можно заранее набрать, что сделано: версию, фамилию, название базы», а если включена передача комментариев (фича 15) — «ИИ составит содержание по задаче, её комментариям и тексту в поле. Можно заранее набрать, что сделано: версию, фамилию, название базы». Кнопка видна, только если в настройках включён флажок «Использовать ИИ», сохранён ключ OpenAI и работа с внешними ресурсами в базе не заблокирована (фича 13). Когда кнопка есть, поле «Содержание» выше: в нём видно 4 строки текста. Иначе кнопки нет, и окно выглядит и работает как до доработки.

Кнопка доступна, когда выбрана задача. ИИ вызывается только нажатием этой кнопки и никогда сам. Нажимать её можно сколько угодно раз: каждое нажатие — новый запрос с текущим текстом поля «Содержание».

После нажатия 1С получает из Битрикс24 описание выбранной задачи (и её комментарии, фича 15) и заново проверяет её по правилам фичи 2 (существование, роль сотрудника, проект режима тестирования), затем обращается к ИИ. Пока идёт запрос, рядом с кнопкой написано «ИИ составляет содержание…», и окно ждёт ответа так же, как при загрузке списка задач: поля и кнопки в это время не нажимаются. Проверка задачи в Битрикс24 вместе с получением комментариев занимает не больше 15 секунд, ответ ИИ ожидается не дольше 30 секунд.

Если Битрикс24 не ответил, ИИ не вызывается и показывается «Битрикс24 недоступен. Попробуйте позже». Если задача больше не подходит, окно показывает сообщение по фиче 2 или 3 и снимает выбор, как при нажатии «Добавить в табель». Эти сообщения, как и ошибки ИИ (фича 12), показываются под полем «Содержание».

### Фича 10. Что передаётся ИИ

ИИ получает:

- название выбранной задачи;
- описание задачи из Битрикс24 без оформления, не больше первых 4000 символов. Из оформления остаётся только текст: у ссылки — её текст, упоминание человека («[USER]Анна Петровна[/USER]») становится его именем, список — строками «- …», таблица — строками из ячеек через « | »; файлы, картинки и видео убираются. Если описание длиннее, ИИ узнаёт, что получил только его начало. Пароли в названии, описании и черновике скрываются (фича 15);
- черновик — текущий текст поля «Содержание». Сотрудник может заранее набрать в нём короткую заметку о сделанной работе, например «обновил бк до 3.0.72.1 у главбуха». Если поле пустое или в нём название задачи, ИИ работает только по названию и описанию;
- стандартные формулировки — все записи справочника «ГЕМ Шаблоны для заполнения табелей», действующие на дату табеля (шифр и описание). Это тот же список, который открывается тремя точками в колонке «Содержание» табеля. Формулировка, добавленная или изменённая в справочнике, используется ИИ сразу, без обновления расширения. Формулировка, которой на дату табеля ещё не было (её добавили позже), берётся в сегодняшней редакции: так новая формулировка видна и в табелях за прошлые дни. Формулировка с пустым описанием на дату табеля снята с использования и не передаётся. Если справочник пуст, ИИ пишет текст только по правилам фичи 11;
- комментарии задачи, если в настройках включён флажок «Передавать ИИ комментарии задачи» (фича 15);
- правила оформления (фича 11), «Дополнительные указания для ИИ» и «Примеры строк табеля» из настроек (фича 13).

ИИ не получает: контрагента из 1С и название компании CRM, ФИО и e-mail сотрудника, имя пользователя 1С, дату табеля, время и тип времени, номер задачи, участников, авторов и даты комментариев, чек-листы и файлы задачи. Названия клиентов и имена, которые есть в самом тексте задачи, комментариев или черновика (в том числе имена из упоминаний), а также телефоны и e-mail из этого текста передаются как часть этого текста.

### Фича 11. Как ИИ составляет текст

В этой фиче «задача» — название, описание и комментарии задачи (комментарии — если они передаются, фича 15). ИИ выбирает стандартную формулировку, которая соответствует работе из задачи и черновика. Если работа охватывает несколько формулировок, они идут подряд. Слова формулировки и их порядок сохраняются: ИИ не пересказывает её и не сокращает. Факты из задачи и черновика ИИ вписывает в формулировку так, как это делают сотрудники в табелях: количество баз («Архив 2ИБ БК. Обновление 2ИБ БК…»), название базы или организации в скобках после ИБ («Архив ИБ БК (ТОО "Ромашка")»), уточнение после значения («до релиза 3.0.75.1, установка патчей», «(на 2 релиза)»). Если в задаче или черновике есть и другая работа, она идёт отдельным предложением. Оформление приводится к правилам ниже, даже если в справочнике оно другое: «31.12.2025 г.» становится «31.12.2025г.», «2026г..» — «2026г.», двойной пробел — одним.

В формулировках есть места, которые сотрудник должен заполнить. В справочнике они записаны так:

- подсказка в скобках: «(чей ПК)», «(название ИБ)», «(рег.номер)», «(рег номер)», «(указать сколько и какие ПК)», «(если надо)»;
- подсказка в кавычках: «ПК "чей"»;
- вопросительные знаки: «в ИБ ???», «на ??? месяцев»;
- точки на месте значения: «3.0.....», «...кв.», «(........)».

В такие места ИИ подставляет значения из задачи и черновика так, как принято в табелях: «(название ИБ)» и «(........)» — название в скобках («(ТОО "Ромашка")»); «(чей ПК)» и «ПК "чей"» — без скобок и кавычек, по правилу «Чей ПК» ниже («на ПК Анны Петровны»); «(указать сколько и какие ПК)» — количество и чьи («на 2ПК (АБ, ВГ)»); «3.0.....» — номер версии («3.0.75.1»); «...кв.» — номер квартала («3кв.»); «???» — значение («на 12 месяцев»). Скобки с пояснением или с настоящим значением местами для заполнения не считаются и остаются как есть: «(продление)», «(новая)», «(30 МРП)», «(БУ/НУ)», «(1С:WebKassa)», перечисления справочников в скобках.

**Чей ПК.** В место «(чей ПК)» или «ПК "чей"» ИИ ставит имя и отчество человека в родительном падеже: «на ПК Анны Петровны». Если в тексте названо только имя, ставится только имя: «на ПК Анны». Фамилия не добавляется, даже если она есть в тексте. Если человек назван только фамилией с инициалами, фамилия ставится в родительный падеж, а инициалы пишутся как в тексте: «Иванова А.П.» — «на ПК Ивановой А.П.». Имя подставляется, только если из задачи или черновика ясно, что это пользователь этого ПК. Если названо несколько людей и не ясно, чей это ПК, место остаётся в тексте, и сотрудник заполняет его сам (фича 12).

Конкретные значения, записанные в формулировке (год, квартал, дата, срок лицензии, номер версии платформы), ИИ заменяет, только если в задаче или черновике прямо названо другое значение. Например, «на 12 месяцев» становится «на 24 месяца», если в черновике написано «на 2 года». Иначе значение остаётся как в справочнике.

Если черновик, комментарии и описание расходятся (например, в них названы разные номера версий), ИИ берёт значение по старшинству: черновик сотрудника, комментарии за день табеля, более ранние комментарии (из двух — более новый), описание, название задачи.

ИИ ничего не выдумывает. Если значения нет ни в задаче, ни в черновике, необязательные места «(название ИБ)», «(........)» и «(если надо)» ИИ убирает (полный список необязательных мест утверждается по справочнику формулировок); если ИИ такое место всё же оставил, его убирает 1С, а остальные места остаются в тексте в том виде, в каком оно записано в формулировке, и попадает в предупреждение (фича 12). Номера версий, ИИН и БИН, регистрационные номера, фамилии, названия организаций и информационных баз переносятся из задачи и черновика символ в символ (имя в месте «чей ПК» ставится в родительный падеж по правилу «Чей ПК»).

Если ни одна стандартная формулировка не подходит (в табелях так в большинстве строк), ИИ пишет текст своими словами в стиле «Примеров строк табеля» из настроек: короткие предложения о выполненной работе («Вопрос по…», «Вопросы по…», «Настройка…», «Проверка…»), без оценок и без пересказа переписки.

Во всех случаях текст соответствует правилам оформления табелей, принятым в боте проверки табелей (`auto_checking_transcript`, системный промт корректора). Правила зашиты в расширение:

- орфография и согласование окончаний;
- написание специальных терминов по эталонному словарю (1С, ИБ, БК, ЭСФ, ЭЦП, ИС ЭСФ, 1C:WebKassa, 1С:Fresh, NCALayer, KaspiBank, Халык и остальные);
- сокращения из словаря не склоняются («по ИТС», «для ЭСФ», «из ИБ»);
- допустимые варианты не заменяются друг на друга («СБ» и «с/б», «СХ» и «с/х», «ЗП» и «з/п», «БЛ» и «б/л», «е» и «ё»);
- фамилия с инициалами пишется как «Иванов И.И.», без пробела между инициалами;
- один пробел между словами и после знака в конце предложения; адреса сайтов и e-mail без пробелов внутри;
- «2026 года», «1 квартал» через пробел; «2026г.», «1кв.» слитно; «2ИБ», «3ПК» слитно;
- сокращения «ф.», «рег.», «физ.лица» не раскрываются; кавычки не меняются;
- текст заканчивается точкой; точка не ставится, если текст кончается на «?», «!» или «…» (так не портится место «???»).

Эталонные формулировки из промта бота в расширение не переносятся: формулировки берутся только из справочника 1С.

«Дополнительные указания для ИИ» из настроек дополняют зашитые правила, а при расхождении с ними действуют указания из настроек. Указания не меняют состав передаваемых данных и вид ответа.

Текст задачи, комментариев и черновика — только материал для содержания. Указания, написанные в них для ИИ (например, «игнорируй правила»), не выполняются.

Ответ — одна строка без переносов и разметки, не длиннее 1000 символов (длина поля «Содержание»). Более длинный ответ обрезается по концу последнего предложения, которое помещается целиком. Если ни одно предложение не помещается, ответ обрезается по последнему целому слову и заканчивается точкой.

### Фича 12. Результат в окне

Ответ ИИ сразу попадает в поле «Содержание» и заменяет прежний текст. Сотрудник может править его как обычно. Курсор встаёт в поле: если в тексте есть незаполненное место, первое из них выделено, и набранное значение заменяет его; иначе курсор стоит в конце текста.

Рядом с кнопкой «Заполнить с помощью ИИ» появляется кнопка «Вернуть прежний текст». Она возвращает текст, который был в поле перед последним нажатием «Заполнить с помощью ИИ», и убирает надписи ИИ под полем. После возврата кнопка исчезает. Помнится только один прежний текст. Кнопка остаётся и после правки поля: она возвращает текст до нажатия ИИ, правки при этом пропадают.

Под полем «Содержание» показываются надписи ИИ:

- «Заполните: ‹места через запятую›», например «Заполните: (чей ПК), 3.0....., ???», если в тексте остались незаполненные места формулировки. Места перечислены в порядке появления в тексте; место, встретившееся в тексте дважды, показывается дважды. Когда сотрудник заполняет место в поле, оно исчезает из надписи; когда заполнены все, надпись исчезает. Кнопка «Добавить в табель» при этой надписи доступна: текст идёт в строку таким, какой он в поле;
- «ИИ не изменил текст», если ответ совпал с текстом в поле. Кнопка «Вернуть прежний текст» в этом случае не появляется. Если в тексте при этом остались незаполненные места, показывается и надпись «Заполните: …». Надпись «ИИ не изменил текст» исчезает, как только сотрудник правит текст;
- «ИИ не получил комментарии задачи», если передача комментариев включена, но 1С не смогла их получить (фича 15): текст составлен без них. Надпись показывается вместе с другими надписями ИИ и не исчезает при правке текста.

Надписи ИИ и кнопка «Вернуть прежний текст» исчезают при выборе другой задачи (поле, как и раньше, заполняется её названием), при снятии выбора (задача, введённая по номеру, не найдена или не подошла) и когда следующее нажатие «Заполнить с помощью ИИ» дало ответ. Повторный выбор той же задачи их не убирает.

Ошибки:

- ИИ не ответил за 30 секунд, вернул ошибку или ответ, который нельзя разобрать, либо превышен лимит запросов: «ИИ недоступен. Заполните содержание вручную»;
- OpenAI отклоняет ключ, модель недоступна для ключа или не поддерживает нужные параметры запроса, закончились средства на счёте или достигнут лимит расходов: «ИИ не настроен. Обратитесь к администратору». Причина записывается в журнал регистрации.

При любой ошибке текст в поле «Содержание» не меняется, кнопка снова доступна, остальное окно работает, строку можно добавить с текстом, набранным вручную. Сообщение об ошибке показывается под полем «Содержание». Ошибка не убирает результат прошлого нажатия: кнопка «Вернуть прежний текст» и надпись «Заполните: …» остаются, надписи «ИИ не изменил текст» и «ИИ не получил комментарии задачи» скрываются.

Строка, добавленная в табель, ничем не отличается от строки с текстом, набранным вручную: отметки об ИИ в табеле нет.

### Фича 13. Настройки ИИ

В форме «Настройки интеграции с Битрикс24» две закладки: «Битрикс24» (поля и кнопки фичи 8) и «ИИ для содержания». Кнопки «Записать и закрыть» и «Закрыть» общие для обеих закладок. Как и вся форма, закладка «ИИ для содержания» доступна только пользователям с полными правами. Поля ИИ доступны и при снятом флажке: ключ можно ввести и проверить до включения.

- **«Использовать ИИ»** — флажок. После установки доработки снят.
- **«Передавать ИИ комментарии задачи»** — флажок (фича 15). После установки доработки снят: администратор включает его, когда передача комментариев задач в OpenAI согласована в компании. Действует, только когда включён «Использовать ИИ». В отличие от остальных настроек флажок действует с ближайшего нажатия «Заполнить с помощью ИИ», даже если окно уже открыто: выключенный флажок сразу останавливает передачу комментариев; подсказка кнопки меняется при следующем открытии окна. Под флажком подсказка: «Вебхуку нужно право «Чат и уведомления»: его показывает «Проверить подключение» на закладке «Битрикс24»». Есть ли право у вебхука, при записи не проверяется.
- **«Ключ OpenAI».** Хранится так же, как адрес вебхука, и в форме не показывается. Под полем написано «Ключ сохранён: sk-…‹последние 4 символа›», например «Ключ сохранён: sk-…AbCd», или «Не указан». Поле ввода после открытия формы и после записи пустое, введённый ключ скрыт, как пароль. Новый ключ, вставленный в поле, заменяет старый. Пустое поле старый ключ не стирает. Кнопка «Удалить ключ» стирает его при записи и снимает флажок «Использовать ИИ». Под полем подсказка: «Создайте ключ API в личном кабинете OpenAI и вставьте его».
- **Проверка ключа при записи.** У ключа убираются пробелы и переносы строк по краям. Принимается ключ, который начинается с «sk-» и состоит из латинских букв, цифр, «-» и «_». Иначе запись не выполняется и показывается «Ключ OpenAI должен начинаться с sk- и не содержать пробелов и русских букв». Ключ администратора OpenAI (начинается с «sk-admin-») не принимается: «Это ключ администратора OpenAI. Создайте ключ API проекта». Работает ли ключ, при записи не проверяется: для этого есть кнопка «Проверить ИИ».
- **«Модель»** — название модели OpenAI, по умолчанию `gpt-5.6-luna`. Пробелы по краям убираются, пустое поле при записи заменяется значением по умолчанию. Название может состоять только из латинских букв, цифр и знаков «.», «-», «_», «:» и быть не длиннее 100 символов. Иначе запись не выполняется: «Название модели может содержать только латинские буквы, цифры и знаки . - _ :». Есть ли такая модель, при записи не проверяется.
- **«Дополнительные указания для ИИ»** — многострочный текст не длиннее 4000 символов. Сюда администратор дописывает новые термины и уточнения правил без обновления расширения. Если текст длиннее, запись не выполняется: «Дополнительные указания для ИИ — не длиннее 4000 символов, сейчас ‹N›».
- **«Примеры строк табеля»** — многострочный текст не длиннее 10 000 символов: хорошо заполненные строки табелей, по одной в строке. По ним ИИ берёт стиль и сокращения. Администратор вставляет сюда обезличенные строки (фамилии, названия организаций, БИН и номера заменены). Примеры хранятся в базе 1С и меняются без обновления расширения. Под полем подсказка: «По одной строке. Фамилии, названия организаций, БИН и номера замените». Если текст длиннее, запись не выполняется: «Примеры строк табеля — не длиннее 10 000 символов, сейчас ‹N›». Если в примерах есть БИН или ИИН (12 цифр подряд, в том числе группами через пробел, например «2345 1261 2395») или e-mail, запись не выполняется: «В примерах строк табеля есть БИН, ИИН или e-mail. Замените их». Фамилии и названия организаций 1С не находит: их заменяет администратор.

У указаний и примеров убираются пробелы и пустые строки по краям, остальной текст хранится как введён.

Если флажок включён, а ключа нет (ни сохранённого, ни введённого), запись не выполняется и показывается «Укажите ключ OpenAI». Когда флажок снят, ключ, модель и указания сохраняются, но не используются.

Если подсистема БСП «Блокировка работы с внешними ресурсами» заблокировала работу с внешними ресурсами (база похожа на копию: её скопировали или перенесли), ИИ не используется: кнопки в окне нет, даже если флажок включён и ключ сохранён. Над полями закладки «ИИ для содержания» тогда написано «База похожа на копию: работа с внешними ресурсами заблокирована, ИИ не используется». Настройки при этом можно менять. Блокировку подтверждает или снимает администратор базы при входе в неё (механизм БСП).

Кнопка **«Проверить ИИ»** стоит рядом с кнопкой «Удалить ключ». Она отправляет короткий проверочный запрос с ключом и моделью из полей ввода и ничего не записывает. Если поле ключа пустое, используется сохранённый ключ, если поле модели пустое — модель по умолчанию. Ключ или название модели неверного вида в OpenAI не отправляются: показывается тот же текст, что при записи. Проверочный запрос идёт с теми же параметрами, что и запрос из окна, но без данных задач. Проверка работает и при снятом флажке «Использовать ИИ», и в базе, похожей на копию. Пока идёт запрос, под кнопками написано «Проверка ИИ…», и кнопка недоступна. Результат показывается под кнопками и исчезает, когда меняется ключ или модель или нажата кнопка «Удалить ключ»:

- «ИИ отвечает. Модель: ‹модель›.» (название модели, которым ответил OpenAI);
- «Не указан ключ OpenAI.»;
- «OpenAI отклоняет ключ.»;
- «Модель ‹модель› недоступна для этого ключа.» (в том числе если модель не поддерживает нужные параметры запроса);
- «На счёте OpenAI закончились средства или достигнут лимит расходов.»;
- «Нет ответа от api.openai.com. Проверьте, что серверу 1С открыт доступ к нему.» (нет связи или нет ответа за 30 секунд);
- «ИИ недоступен. Попробуйте позже».

Изменения настроек начинают действовать при следующем открытии окна «Заполнить из задачи Битрикс24». Если ИИ выключили, ключ удалили или база стала копией, пока окно открыто, кнопка остаётся до закрытия окна, но по нажатию ничего не отправляется ни в Битрикс24, ни в OpenAI и показывается «ИИ не настроен. Обратитесь к администратору». Настройки ИИ и настройки Битрикс24 записываются одной кнопкой «Записать и закрыть». Если ошибка есть на любой закладке, показываются все ошибки сразу и ничего не записывается, в том числе настройки Битрикс24.

### Фича 14. Связь с OpenAI и безопасность

Сервер 1С обращается к OpenAI напрямую по HTTPS с проверкой сертификата. Серверу 1С нужен исходящий доступ к `api.openai.com`. Бот проверки табелей в этой связи не участвует и продолжает работать отдельно.

Ключ OpenAI хранится только в безопасном хранилище 1С. Он не попадает в журнал регистрации, сообщения, на клиент и ни в одну форму; в форме настроек он не показывается после записи.

Одно нажатие кнопки — один запрос к ИИ, без автоматических повторов. В журнал регистрации записывается каждое обращение: кто обратился, сколько оно длилось, чем закончилось и сколько токенов потрачено; для «Содержания» — ещё «написано своими словами», шифры использованных формулировок и сколько комментариев передано (фича 15). Текст задачи и комментариев, черновик, ответ ИИ и ключ в журнал не записываются.

ИИ ничего не записывает: ни в Битрикс24, ни в базу 1С. Табель, как и раньше, записывает сам сотрудник. В режиме тестирования ИИ работает так же, как в обычном.

### Фича 15. Комментарии задачи для ИИ

Если в настройках включён флажок «Передавать ИИ комментарии задачи» (фича 13), то при нажатии «Заполнить с помощью ИИ» 1С получает из Битрикс24 ещё и комментарии выбранной задачи и передаёт их ИИ вместе с названием, описанием и черновиком (фича 10). Так содержание получается полным и без черновика. Например, в формулировку «Установка 1С-Коннект на ПК "чей"» ИИ подставляет человека, названного в комментариях: «Установка 1С-Коннект на ПК Анны Петровны.» Если значения нет и в комментариях, место остаётся, и сотрудник дописывает его в поле «Содержание» в окне (фича 12). ИИ, как и раньше, вызывается только кнопкой, а не при выборе задачи (фича 9).

**Какие комментарии передаются.**

- Комментарии — это сообщения чата задачи (новая карточка задачи Битрикс24). Системные сообщения чата («создал задачу», смена статуса или крайнего срока, приглашение в чат и подобные), удалённые сообщения и сообщения ботов не передаются. У задачи без чата комментариев нет.
- Передаются комментарии всех участников, написанные до конца дня табеля включительно. Комментарии, написанные после дня табеля, не передаются: они о работе следующих дней.
- Комментарии, написанные в день табеля, помечены для ИИ: по ним он описывает работу этого дня, а из более ранних берёт факты (имя, версию, название базы). Ни дата табеля, ни даты комментариев в OpenAI не передаются, только эта пометка.
- Комментарии самого сотрудника помечены как его. Имена и другие данные авторов комментариев не передаются: так ИИ не подставит в «чей ПК» имя коллеги, написавшего комментарий.
- Работу дня табеля ИИ берёт из черновика и из комментариев самого сотрудника за этот день. Из комментариев коллег он берёт факты и просьбы (кто просил, какая база, какая версия), а работу, которую коллега сделал сам, в текст сотрудника не пишет. Если своих комментариев за день табеля нет, работа дня берётся из всех комментариев этого дня.
- Оформление убирается так же, как в описании (фича 10): упоминание человека становится его именем, файлы, картинки и видео убираются. Цитата, вставленная кнопкой «Цитировать» (имя автора, дата и текст старого сообщения), убирается из комментария целиком: процитированное сообщение передаётся само по себе со своей пометкой. Комментарий, в котором после этого не осталось текста (например, только файл), не передаётся.
- Один комментарий передаётся не длиннее 1500 символов: от более длинного (например, вставленного текста ошибки) — начало по целому слову, и ИИ знает, что комментарий обрезан. Всего передаётся не больше 6000 символов комментариев. Если их больше, отбрасываются самые старые, и ИИ узнаёт, что получил не все. 1С просматривает не больше 200 последних сообщений чата: более ранние не передаются.

**Пароли.** Перед отправкой в OpenAI 1С скрывает пароли во всём, что уходит ИИ: в названии и описании задачи, в комментариях и в черновике. Слова-ключи — «пароль» в любой форме («пароля», «паролем», «пароли»), «password», «pass», «passwd», «пасс» и «pwd»: отдельным словом, в любом регистре. Если после слова-ключа (сразу или через одно-три слова) стоит знак «:», «=», «-» или «—», значение после знака до пробела, запятой, точки с запятой или точки в конце заменяется на «***»; значение в кавычках скрывается целиком. Если знака нет, скрывается следующее слово, только если в нём есть латинские буквы или цифры. Например, «пароль: Qwerty123» становится «пароль: ***», «pwd=Qwerty123» — «pwd=***», «пароль от RDP: Qwerty123» — «пароль от RDP: ***», «пароли: admin/Qwerty123» — «пароли: ***», «password Qwerty» — «password ***»; «сменил пароль пользователю Анне», «паролей нет» и «без пароля» не меняются. Остальной текст не меняется: регистрационные номера, номера версий, БИН и ИИН нужны для формулировок и не скрываются. Пароль, записанный без этих слов, и пароль из одних русских букв без знака после слова-ключа 1С не распознаёт. «***» ИИ в текст не переносит.

**Права и доступ.**

- Комментарии читаются тем же вебхуком (фича 8), и у него должно быть право «Чат и уведомления»; «Проверить подключение» показывает, есть ли оно. Функция по-прежнему ничего не записывает в Битрикс24, в том числе в чат задачи, и не отмечает комментарии прочитанными.
- Битрикс24 отдаёт сообщения чата задачи только тем, у кого есть доступ к этому чату. Отдаёт ли он их администратору — владельцу вебхука в задачах, где тот не участник, проверяется до разработки (TASKS.md, этап 22). Если не отдаёт, комментарии в этой доработке не используются, а как быть, решается заново.

**Если комментарии не получены.** Если у вебхука нет права «Чат и уведомления», Битрикс24 отказал в доступе к чату задачи или не ответил на запрос комментариев, или истекли 15 секунд на запросы к Битрикс24 (фича 9), ИИ составляет текст без комментариев, как при снятом флажке, а под полем «Содержание» показывается «ИИ не получил комментарии задачи» (фича 12). Причина записывается в журнал регистрации. Если Битрикс24 отдал часть комментариев, а на следующей порции не ответил или истекли 15 секунд, ИИ получает то, что пришло (это самые новые комментарии), и знает, что получил не все; надпись показывается, только если не передано ни одного комментария. Если флажок снят, комментарии не запрашиваются и надписи нет.

**Журнал регистрации.** К записи об обращении к ИИ (фича 14) добавляется, сколько комментариев и сколько символов комментариев передано и были ли они обрезаны. Текст комментариев в журнал не записывается.

### Сценарии приёмки

- **С16.** Сотрудник выбирает задачу про обновление базы, набирает в «Содержание» «обновил бк до 3.0.72.1» и нажимает «Заполнить с помощью ИИ». В поле появляется стандартная формулировка обновления из справочника с версией 3.0.72.1, надписей под полем нет. Строка добавляется в табель с этим текстом.
- **С17.** В задаче и черновике нет значения для места формулировки. В тексте остаётся «(чей ПК)», под полем написано «Заполните: (чей ПК)». Сотрудник вписывает значение — надпись исчезает. Строку можно добавить и с незаполненным местом.
- **С18.** Работа из задачи не подходит ни под одну формулировку. ИИ пишет текст своими словами в стиле «Примеров строк табеля» и по правилам оформления; надписей ИИ под полем нет.
- **С19.** После ответа ИИ сотрудник нажимает «Вернуть прежний текст»: в поле прежний текст, надписи ИИ и кнопка исчезли.
- **С20.** Флажок «Использовать ИИ» снят, ключ не указан или база заблокирована как копия: кнопки «Заполнить с помощью ИИ» в окне нет, окно работает как до доработки.
- **С21.** OpenAI недоступен: «ИИ недоступен. Заполните содержание вручную», текст в поле не изменился, строка добавляется с текстом, набранным вручную. Ключ неверный: «ИИ не настроен. Обратитесь к администратору».
- **С22.** В настройках ключ после записи не показывается, «Удалить ключ» стирает его и снимает флажок, включить флажок без ключа нельзя, «Проверить ИИ» показывает результат по фиче 13.
- **С23.** В справочник шаблонов добавлена новая формулировка. Без обновления расширения ИИ использует её для подходящей задачи.
- **С24.** После всех сценариев в журнале регистрации нет ключа OpenAI, текста задач, комментариев, черновиков и ответов ИИ.
- **С25.** Сотрудник в черновике пишет термины с ошибками и в неверном регистре («эсф», «иб», «бухгалетер»). В ответе ИИ они исправлены по правилам фичи 11, а фамилии, номера версий и БИН перенесены без изменений.
- **С26.** Флажок «Передавать ИИ комментарии задачи» включён. В задаче об установке 1С-Коннект пользователь ПК назван только в комментарии («Анна Петровна просит поставить 1С-Коннект»), черновик пустой. ИИ пишет «Установка 1С-Коннект на ПК Анны Петровны.», надписи «Заполните: …» нет.
- **С27.** В комментариях названо несколько людей, и не ясно, чей ПК: место остаётся в тексте, под полем написано «Заполните: "чей"». Сотрудник вписывает имя в поле, надпись исчезает.
- **С28.** По долгой задаче работа дня табеля описана в комментарии за этот день, а в более ранних комментариях — другая работа. ИИ описывает работу дня табеля и берёт из ранних комментариев только факты; комментарии, написанные после дня табеля, на текст не влияют.
- **С29.** Флажок включён, а у вебхука нет права «Чат и уведомления»: текст составлен без комментариев, под полем написано «ИИ не получил комментарии задачи»; «Проверить подключение» показывает «Чат и уведомления — нет». При снятом флажке комментарии не запрашиваются, окно работает по фичам 9–14.
- **С30.** Пароль из комментария и из описания («пароль: Qwerty123») в OpenAI не уходит: в запросе вместо него «***».

### Вне рамок

- Проверка и исправление «Содержания» в уже добавленных строках и во всём табеле: это остаётся в боте.
- Окно «Подбор содержания в табель» (три точки в колонке «Содержание») и подстановка описания по шифру не меняются.
- ИИ не предлагает время, тип времени и контрагента.
- Чек-листы и файлы задачи не используются; комментарии — только по фиче 15.
- Комментарии старой карточки задачи (форум) не читаются.
- Запись в чат задачи, в том числе отметка о прочтении комментариев.
- История запросов и ответов ИИ не хранится.
