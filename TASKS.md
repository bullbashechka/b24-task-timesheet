# TASKS: Заполнение табеля 1С из задачи Битрикс24

План работ по [PRD.md](PRD.md). Ссылки вида «Ф3» указывают на фичи PRD, «С5» — на сценарии приёмки.

Порядок этапов: 0 → 1 → (2, 3, 4 параллельно) → 5 → 6 → 7 → 8 → 9.
Этап 0 — точка «идём / не идём»: если браузеры блокируют обращение к 1С из окна Битрикс24, архитектура пересматривается до начала основной разработки.

---

## Этап 0. Проверка осуществимости (прототип в браузерах)

Цель: убедиться, что страница с сервера 1С в офисной сети открывается внутри карточки задачи Битрикс24 и может обращаться к HTTP-сервису 1С.

- [ ] **0.1.** Опубликовать на демо-базе КА минимальный HTTP-сервис в расширении `Б24ПрототипЭтап1`: одна HTML-страница и один JSON-метод (`ping`).
- [ ] **0.2.** Выпустить и установить HTTPS-сертификат для публикации 1С, которому доверяют браузеры сотрудников (см. 1.2; для прототипа — тот же сертификат).
- [ ] **0.3.** Зарегистрировать черновое локальное приложение Битрикс24 со встройкой в карточку задачи, указывающей на страницу из 0.1.
- [ ] **0.4.** Проверить в **Firefox 151+**: окно открывается в карточке задачи, страница грузится, запрос `ping` из страницы в 1С проходит. Зафиксировать, появляется ли запрос разрешения на доступ к локальной сети и что происходит при отказе.
- [ ] **0.5.** Повторить 0.4 в Chrome и других браузерах, которыми пользуются сотрудники (составить список браузеров и версий).
- [ ] **0.6.** Проверить с компьютера вне офисной сети: страница не открывается / запрос не проходит — понять, как это выглядит для пользователя (нужно для сообщения «1С недоступна», Ф4).
- [ ] **0.7.** Записать результат проверки и решение: оставляем публикацию в локальной сети или переходим на публикацию 1С в интернете по HTTPS.

**Готово, когда:** во всех целевых браузерах окно открывается и обращается к 1С, либо принято и записано альтернативное решение.

## Этап 1. Инфраструктура и настройки

- [ ] **1.1.** Публикация демо-базы КА на веб-сервере в офисе (страница окна + HTTP-сервис).
- [ ] **1.2.** HTTPS для публикации: постоянный сертификат, доверенный браузерами сотрудников; DNS-имя сервера 1С.
- [ ] **1.3.** Исходящий доступ сервера 1С в интернет к порталу Битрикс24 (HTTPS), проверка вызова REST с сервера.
- [ ] **1.4.** Настройки интеграции в 1С (константы или регистр сведений в расширении):
  - адрес портала Битрикс24 (из окна не принимается);
  - технический пользователь интеграции (автор табеля, если у сотрудника нет пользователя 1С);
  - флаг «режим тестирования» и ID проекта «[ТЕСТ] Табель из задачи» (для этапа 5).
- [ ] **1.5.** Создать технического пользователя интеграции в демо-базе КА с правами на чтение/запись/проведение `гем_Табель` и чтение справочников (физлица, пользователи, контрагенты, типы времени).

**Готово, когда:** с сервера 1С успешно выполняется REST-запрос к порталу, страница 1С открывается по HTTPS без предупреждений.

## Этап 3. HTTP-сервис 1С (Ф2, Ф4, Ф5, Ф6)

Сервис в расширении `Б24ПрототипЭтап1`. Окно передаёт только номер задачи и токен пользователя Битрикс24; всё остальное 1С получает из Битрикс24 сама. В CRM ничего не записывается.

### 3.1. Клиент REST Битрикс24
- [ ] **3.1.1.** Общий модуль для вызова REST портала от имени пользователя по его токену (адрес портала — из настроек 1.4).
- [ ] **3.1.2.** Обработка ошибок: истёкший/неверный токен, нет доступа, недоступность портала, таймауты.
- [ ] **3.1.3.** Получение текущего пользователя (`user.current`): ID и e-mail.
- [ ] **3.1.4.** Получение задачи (`tasks.task.get`): номер, название, постановщик, исполнитель, соисполнители, проект, привязанные элементы CRM.
- [ ] **3.1.5.** Получение реквизитов компании (`crm.requisite.list` по компании, в порядке отображения в карточке) и названия компании (`crm.company.get`).

### 3.2. Проверка роли (Ф2)
- [ ] Пользователь должен быть постановщиком, исполнителем или соисполнителем; иначе — ответ «нет прав» с текстом «Заполнять табель по задаче могут только постановщик, исполнитель и соисполнители». Статус задачи не учитывается. Проверка выполняется и при открытии окна, и при добавлении строки.

### 3.3. Сопоставление сотрудника по e-mail (Ф4)
- [ ] Найти пользователя 1С или физическое лицо с e-mail пользователя Битрикс24 (сравнение без учёта регистра и пробелов). Результат — физлицо сотрудника и (если есть) пользователь 1С.
- [ ] Если не найден — ответ «не связан» с текстом «Ваш пользователь Битрикс24 не связан с сотрудником 1С. Обратитесь к администратору».

### 3.4. Определение контрагента (Ф6)
- [ ] Выбор компании из «Элементов CRM»: ровно одна компания → она; несколько → «несколько компаний»; нет компании (только сделки/контакты и пр.) → «не указана компания». Компании из сделок/контактов не подтягиваются.
- [ ] Нет прав на чтение компании → «Нет доступа к компании CRM».
- [ ] БИН/ИИН из первого реквизита, где он заполнен; удаление пробелов. Нет ни одного → «У компании «‹название›» не заполнен БИН».
- [ ] Поиск контрагента 1С по полю «ИНН», без помеченных на удаление: 0 → «не найден в 1С», >1 → «несколько контрагентов», 1 → контрагент.
- [ ] Все тексты причин — строго по таблице Ф6.

### 3.5. Метод «Открытие окна» (`init`)
- [ ] Вход: номер задачи, токен. Выход: номер и название задачи, статус доступа (ок / нет прав / не связан / функция в тестировании), контрагент или причина, список типов времени, тип по умолчанию «Клиент (УД)».

### 3.6. Метод «Добавить в табель» (`add`)
- [ ] Вход: номер задачи, токен, дата, время начала, время окончания (необязательно), тип времени, содержание.
- [ ] Повторить проверки 3.2, 3.3, 3.4 на стороне 1С (данным из окна не доверять, кроме введённых полей).
- [ ] Серверная валидация полей: дата не позже сегодняшней, время начала обязательно, кратность 5 минутам, окончание позже начала, тип времени существует.

### 3.7. Поиск или создание табеля (Ф4)
- [ ] Найти табель сотрудника за выбранную дату, не помеченный на удаление.
- [ ] Если нет — создать: дата = выбранная дата + текущее время, сотрудник, организация по умолчанию (2.5), автор = пользователь 1С сотрудника или технический пользователь.
- [ ] Определить поведение, если табелей за дату несколько (уточнить у заказчика; по умолчанию — первый по дате документа).

### 3.8. Добавление строки (Ф5)
- [ ] Новая строка: Контрагент (или пусто), Тип времени, Время нач., Время кон. (или пусто), Содержание, ID Б24 = номер задачи. Тип ПП не заполнять.
- [ ] При наличии времени окончания — расчёт Факт/Норма/К оплате тем же алгоритмом, что при ручном вводе (2.4).
- [ ] Повторное добавление всегда создаёт новую строку, существующие не меняются.

### 3.9. Запись и транзакционность (Ф4)
- [ ] Проведённый табель перепроводить, непроведённый — записывать.
- [ ] Всё в одной транзакции: при любой ошибке в 1С ничего не меняется.
- [ ] Управляемая блокировка/проверка, что табель не редактируется: текст «Табель за ‹дата› сейчас редактируется в 1С — закройте его и повторите».
- [ ] Дата запрета изменения и ошибки проведения — вернуть текст ошибки 1С в окно.
- [ ] Ответ при успехе: дата табеля для сообщения «Строка добавлена в табель за ‹дата›».

### 3.10. Журналирование
- [ ] Записывать в журнал регистрации вызовы сервиса и ошибки (без токенов).

**Готово, когда:** методы `init` и `add` отрабатывают все ветки Ф2, Ф4, Ф5, Ф6 при вызове вручную (curl/тестовая страница) с токеном реального пользователя.

## Этап 4. Окно заполнения строки табеля (Ф3)

HTML/JS-страница, отдаётся HTTP-сервисом 1С, работает внутри окна Битрикс24 (BX24.js).

- [ ] **4.1.** Получение номера задачи из параметров встройки и токена пользователя через BX24.js; вызов `init`.
- [ ] **4.2.** Состояние загрузки при открытии окна.
- [ ] **4.3.** Экраны-заглушки (только сообщение + «Закрыть»): нет прав (Ф2), функция в тестировании (этап 5).
- [ ] **4.4.** Шапка: номер и название задачи.
- [ ] **4.5.** Поля:
  - Дата — календарь, по умолчанию сегодня (часы компьютера), запрет будущих дат, нижней границы нет;
  - Время начала — обязательно, шаг 5 минут, по умолчанию текущее время, округлённое вниз до 5 минут;
  - Время окончания — необязательно, шаг 5 минут, позже начала;
  - Тип времени — список из 1С, по умолчанию «Клиент (УД)»;
  - Содержание — по умолчанию полное название задачи, свободный текст;
  - Контрагент — только чтение: наименование с пометкой «найден в 1С» или текст причины из Ф6.
- [ ] **4.6.** Валидация: подсказка у ошибочного поля, кнопка «Добавить в табель» недоступна, пока есть ошибки.
- [ ] **4.7.** Сотрудник не связан с 1С: сообщение сразу при открытии, кнопка «Добавить в табель» недоступна.
- [ ] **4.8.** «Добавить в табель»: блокировка кнопки на время запроса (защита от двойного нажатия), вызов `add`.
- [ ] **4.9.** Успех: вместо полей — «Строка добавлена в табель за ‹дата›» и «Закрыть».
- [ ] **4.10.** Ошибки 1С: окно остаётся открытым с введёнными данными, показывается текст ошибки из 1С.
- [ ] **4.11.** 1С недоступна (при открытии и при добавлении): «1С недоступна. Проверьте, что компьютер подключён к сети офиса, и попробуйте позже», данные сохраняются.
- [ ] **4.12.** «Отмена» / «Закрыть» — закрытие окна через BX24.js без изменений в 1С.
- [ ] **4.13.** Вёрстка под размеры окна Битрикс24, проверка в целевых браузерах.

**Готово, когда:** все состояния окна из Ф3 и Ф4 воспроизводятся на демо-базе КА.

- [ ] **5.2.** Встройка в блок «Приложения» новой карточки задачи — пункт «Заполнить табель» (код встройки уточнить по документации Битрикс24).

- [ ] **5.5.** Режим тестирования:
  - в карточке — кнопка видна только в задачах проекта «[ТЕСТ] Табель из задачи» (выяснить механизм ограничения встройки; если невозможно — использовать заглушку 5.5.2);

- [ ] **5.6.** Убедиться, что приложение ничего не пишет в CRM и в задачи (ревью кода сервиса 1С).

**Готово, когда:** кнопка доступна в карточке и в списке задач, открывает рабочее окно; ограничение режима тестирования работает.
